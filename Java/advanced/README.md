# 템플릿 메서드 패턴 

1. 장점 
* 중요 로직을 execute(), call() 메서 등등으로 abstract 추상 클래스를 통해 처리함.
* 공통 로직과 중요한 비지니스 로직이 분리가 가능.
2. 단점

* 상속이기 때문에, Template을 사용한 모든 클래스를 수정해야 하는 문제가 발생.
* Template에 사용하는 클래스를 제네릭으로 받다보니 모든 클래스에서 사용하는 템플릿 메서드 사용하는 모든 자료형이 다를 가능성이 높음.

# 전략 패턴

* 변하지 않는 Context , 인터페이스를 위임 받아 처리함.
* call() 중요 비지니스 로직을 처리하는 부분을 인터페이스로 정의
* call()을 상속받는 클래스는 전략에 따라 교체가 가능함.
